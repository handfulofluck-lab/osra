PART 1 Start the Hub (your PC)

1

Protect your test (1 minute, recommended). The server will be visible on the internet, so let's set secret passwords for it.

Right-click start-backend.bat → Edit (opens in Notepad). Find these three lines:

set JWT_SECRET=CHANGE_ME...
set INTERNAL_HMAC_SECRET=CHANGE_ME...
set VAULT_KEY=CHANGE_ME...

Replace each value with 20+ random letters and numbers (just mash your keyboard — no spaces). Then save and close Notepad.

2

Start the server. Double-click start-backend.bat.

The first time, a black window will show some setup text and then say the server is starting. Leave this window open — the server runs inside it.

3

Check it's alive. Open your web browser and go to:

http://localhost:3000/health

You should see {"ok":true,"version":"0.1.0"}. ✅ Part 1 done!

Technical helper note: /health only proves the API process is up. If apps ever fail while it looks fine, check http://localhost:3000/health/deep — a 503 or "db":"down" there means the database service (OSRA-Postgres) stopped; run net start OSRA-Postgres.

⚠️ Keep the window open If you close the black window, the server stops and the apps will go offline. If the PC restarts, just double-click start-backend.bat again.

PART 2 Put the Hub online with Cloudflare

Your home internet doesn't give the server a public address, so we use a free tool from Cloudflare that creates a secure public link (https://…) to your PC. This is completely free and takes ~5 minutes.

1

Download the tool. Open this page in your browser:

https://github.com/cloudflare/cloudflared/releases/latest

Under Assets, click the file named:

cloudflared-windows-amd64.exe

Save it to your Downloads folder.

2

Open a command window in Downloads. Open File Explorer, go to Downloads, then in the folder's address bar type cmd and press Enter. A black window opens.

3

Start the tunnel. Copy this whole line, paste it into the black window with right-click, then press Enter:

cloudflared-windows-amd64.exe tunnel --url http://localhost:3000

Wait about 10 seconds. You'll see lots of text, then a line like:

https://acm-julian-manitoba-engaged.trycloudflare.com
4

Copy your address. The https://…trycloudflare.com address is yours. Write it down and paste it into the green box at the top of this page (📋), then click Save my address.

This window must also stay open while you test.

ℹ️ About the address It's randomly generated and changes every time you restart the tunnel. That's fine for a single test day — if you restart it, just share the new address with your testers. For a multi-day test you can get a fixed address with a free ngrok account instead (ask your technical helper, or see the Troubleshooting section).
✅ Quick check On your phone's browser, open https://your-address.trycloudflare.com with /health at the end. Seeing {"ok":true} means the whole online path works!

PART 3 Install the Parent app 📱 (parent's phone)

1

Copy OSRA-Parent.apk to the parent's phone (email it, WhatsApp it, USB cable — any way works).

2

Tap the file. The phone will warn about "unknown apps" — tap Settings on that popup and allow installs from that app (e.g. your file manager or browser). Then go back and tap Install.

3

Open OSRA. You'll see a login screen with three boxes. Fill them in:

  • Server: https://your-address.trycloudflare.com (your address from Part 2)
  • Email: demo@familyshield.dev
  • Password: CorrectHorseBatteryStaple!

Tap Sign in.

4

You should see a dashboard with a child named Alex and a device. 🎉 (Or tap Create account on the login screen to make your own family instead.)

PART 4 Set up the child's Android phone 🧒📱

1

Get a pairing code. On the parent phone, open Alex's page → tap Pair a device. A big 6-digit code appears — it's valid for 10 minutes.

2

On the child's phone, install OSRA-ChildAgent.apk the same way you installed the parent app (allow unknown apps → Install).

3

Open the app. Fill in:

  • Server URL: https://your-address.trycloudflare.com
  • Pairing code: the 6 digits from step 1

Tap Pair this device. If it says the code is invalid, the 10 minutes may have passed — just generate a fresh code on the parent phone.

4

Turn on the supervision service. On the success screen, tap Open accessibility settings → find OSRA in the list → turn it On → confirm. This is what lets the app block other apps.

5

Allow location. When asked, choose Allow all the time (not just "while using the app") so location updates keep working.

A persistent notification "Location sharing is active" tells you everything is running.

6

Back on the parent phone, the device now appears on Alex's page within a minute, showing status and battery. ✅ Done!

ℹ️ Phone tip Some phones (Xiaomi, Huawei, Samsung) aggressively kill background apps. If the child phone stops reporting later, open the agent app once — and in the phone's battery settings, set OSRA to "No restrictions".

PART 5 Set up the child's Windows PC 🧒🖥️

1

On the parent phone, generate a fresh pairing code (child's page → Pair a device).

2

Copy the folder OSRA-Agent-Windows to the child's PC (USB stick, shared folder, etc.).

3

Double-click OSRA.Agent.exe. The first time, a pairing window opens. Enter:

  • Server URL: https://your-address.trycloudflare.com
  • Pairing code: the 6 digits from step 1

Tap Pair. The window closes and the agent keeps running in the background (a console window — leave it open).

4

The PC is now supervised: its web browsing is filtered, blocked apps are closed, and screen-time limits apply. The device appears in the parent app within a minute.

ℹ️ Details for the curious The screen-time lock screen unlocks with PIN 0000 (ask your technical helper to change it via the DESKTOP_PARENT_PIN setting if needed). To uninstall later: delete the OSRA-Agent-Windows folder and remove the proxy in Windows Settings → Network → Proxy (it turns off automatically when the agent exits).

PART 6 Try it out! 🎉

Everything is set up. Here's a fun checklist to see OSRA in action:

  • Block an app: parent app → Alex → Rules → Apps → set an app (e.g. YouTube) to Block → Save. Within ~1 minute, opening it on the child's phone shows "This app is blocked by your parent".
  • Control the device: on the child's page, each device card has Ring, Lock and Unlock buttons. Tap Lock — within ~1 minute the PC shows a full-screen "locked by parent" screen that only a parent PIN (default 0000) can dismiss; Unlock releases it remotely. Ring makes the device beep.
  • Web filter: on the child PC, try opening a gambling site — you get the "Blocked by OSRA" page immediately. Google searches run in SafeSearch.
  • See alerts: everything the child tries generates an alert on the parent's Alerts screen in real time. Swipe one away to acknowledge it.
  • Watch the map: the Map screen shows the child's live location and the Home/School geofences. (If the map area looks empty, the Google Maps key is not configured — locations and all controls still work from the child's page.)
  • New in this release: tap the Internet pill on a child card to pause the internet; open the child's Social tab and try the test phrase "kill yourself" on the child's WhatsApp — an alert with the snippet and a coach card arrives within a minute; grant Bonus time (+30) from the child's page; try the child's SOS quick-settings tile; invite a co-parent from the dashboard menu → Family members. All 29 features: SHIP-NOTES.md.
  • Bedtime: set the bedtime window to cover the current time → both the phone and the PC lock the child out.

🛠️ If something goes wrong

ProblemWhat to do
Apps say "Internal Server Error" but the health test worksThe API is running but the database behind it stopped. On the PC, open a command window and run net start OSRA-Postgres, then close and re-open start-backend.bat. (Prevention: it normally runs as an automatic Windows service.)
Phone says "can't connect" or "timeout"The server or tunnel stopped. Check both black windows on the PC are still open. Re-open start-backend.bat, restart the tunnel, and re-check the /health test from Part 2.
The address stopped working after a PC restartThe tunnel address changes when restarted. Use the new address in the app's Server field (parent app login screen; on the child phone use Re-pair; on the child PC delete agent.config.json next to the exe and run it again).
"Invalid or expired code" when pairingCodes last 10 minutes and work once. Generate a new code on the parent phone.
Child phone isn't blocking appsThe accessibility service is off — open the agent app on the child phone and tap "Open accessibility settings" to re-enable it. Also make sure the agent app isn't force-stopped.
Child PC isn't filtering websitesThe agent's console window must be open. Plain-HTTP pages are filtered out of the box; real sites use HTTPS, which is filtered after a one-time opt-in — see "HTTPS sites not blocked on the PC" below. To see blocking right away: add a domain to the child's blocked list in Rules, then open its http:// version (e.g. http://neverssl.com). On Firefox also set Settings → General → Network Settings → Use system proxy settings. Blocked attempts show up as alerts.
Map shows no locationOn the child phone, location permission must be "Allow all the time", and GPS must be on. Testing on an emulator? GPS injection doesn't reach the agent reliably — verify location on a physical phone.
Everything is slow to react (up to a minute)Normal! Test builds don't use push notifications — devices check in with the server every ~60 seconds.
Social concerns don't appearWhatsApp monitoring must be ON (child's Social tab), the accessibility service enabled, and the message from a monitored app — allow a minute for the phone's check-in loop.
Paused device still opens some appsThose apps are in "Always allowed" (Rules → Apps). Remove them to block everything while paused.
Calls/texts list is emptyGrant "Call & SMS permissions" from the agent app's completion screen (optional). iOS can't monitor calls/texts.
HTTPS sites not blocked on the PCHTTPS filtering is opt-in: run setx FS_HTTPS_INSPECT 1 on the child PC, restart the agent, approve the certificate prompt once.
I need the same address for several daysQuick tunnels change address on restart. Ask your technical helper to set up a free ngrok static domain or a Cloudflare named tunnel — instructions are in the README for technical helpers.

# Arabic look-alike families — codepoint plan (draft, no Arabic strings)

K31-Mac's own-model data unit (Claude `7127335158`). This file is **research only**: it names Unicode
codepoints and their confusable partners so the row generator is a mechanical step once the format and the
Arabic-as-data boundary are answered (`7128414966`). No Arabic strings are written here, and nothing in this
file is user-facing copy.

## Why codepoints first

A look-alike set is only useful if each row says *which* distinction a detector must keep. Writing the
families as `U+xxxx` pairs makes the row generation mechanical, reviewable without an Arabic reader, and
impossible to confuse with product copy.

## Families worth rows

| Family | Members (codepoints) | The trap |
|---|---|---|
| Alef forms | U+0627, U+0623, U+0625, U+0622, U+0671 | Four visually-near forms plus a Quranic alef; normalising all to bare alef hides a deliberate substitution |
| Yaa / alef maqsura | U+064A, U+0649, U+06CC | Persian yaa is common in loanwords; collapsing it can change a word's identity |
| Taa marbuta / haa | U+0629, U+0647 | Word-final only; the substitution is invisible at small sizes |
| Kaf variants | U+0643, U+06A9 | Persian/Urdu kaf; matters because the product ships Urdu (Neon's unit) |
| Heh variants | U+0647, U+06C1, U+06D5 | Urdu heh goal is a different letter, not a decoration |
| Digit sets | U+0660–U+0669 (Arabic-Indic), U+06F0–U+06F9 (Extended), U+0030–U+0039 (ASCII) | Normalising digits is right for search and wrong for a verification code |
| Tatweel | U+0640 | Zero-width-ish elongation; stripping it is usually correct, keeping it can defeat a naive match |
| Diacritics | U+064B–U+0652, U+0670 | Stripping is normal for search, lossy for quoted text |
| Zero-width | U+200B–U+200D, U+FEFF | Invisible; the honest row is "this string differs only by an invisible character" |
| Presentation forms | U+FB50–U+FDFF, U+FE70–U+FEFF | Rendering forms that should normalise to base letters |
| Arabic-Indic vs Latin percent/commas | U+066A, U+060C, U+061B | Punctuation that reads as `%`, `,`, `;` but is not them |

## Row shape I intend (subject to the real convention)

One JSON object per line, fields in English, the Arabic sample carried as an escaped codepoint sequence so a
reviewer can read the structure without trusting a copy-paste:

```json
{"id":"ar-look-0001","family":"alef-forms","samples":["\u0627","\u0623"],"relation":"visually-near",
 "why":"bare vs hamza-above alef","source":"unicode-names","is_ui_text":false}
```

`is_ui_text: false` is the boundary: none of these rows may be lifted into a shipped `.strings`/`.arb` file,
and any row that a screen would display goes to #604 instead.

# Evaluation results — the child-safety scorer

Plan 4.3: precision and recall per category, per language, published in the repository and
regenerated by a command rather than transcribed by hand. Plan 4.2 supplies the labelled set this
measures against (`services/ai-engine/eval/`).

```bash
cd services/ai-engine
python -m eval.generate                     # rebuild eval/dataset.jsonl from the template banks
python -m eval.run_eval --scorer regex --write-md EVAL.md
```

## The headline

**Arabic recall is 0.00 in all seven categories, and English flags 30 % of harmful rows.** That is
not a regression — it is plan 4.1's premise, measured instead of assumed. The rules layer in
`model.py` is a set of English regular expressions; not one of them can match Arabic script, so
Arabic text is "safe" by construction no matter what it says. On the English side the layer does what
a keyword list can: it catches the categories whose vocabulary is distinctive (`sexual_content` 0.73,
`substance_use` 0.57) and misses the ones phrased as intent (`self_harm` 0.05, `hate_speech` 0.00,
`violence` 0.13), because those are said in sentences, not in words.

`n/a` in the precision column means the scorer flagged **nothing** in that category, so precision is
undefined rather than zero — printing 0.00 there would read as "every flag was wrong" when in fact
none was raised.

This is the number the hosted scorer (4.1) has to beat, and the reason the gate in `docs/ROADMAP.md`
is written as recall ≥ 0.85 at precision ≥ 0.6 rather than "the tests pass".

## How to read these numbers

- **`support`** is the number of rows labelled with that category. It is 65 per category per language,
  plus the rows another bank also labels with it: a true overlap carries both labels (an adult asking
  a child for a photo is `grooming` *and* `sexual_content`), so `cyberbullying` in English has 82
  rows — 65 of its own and 17 shared. A scorer that answers either label has read the row correctly.
- **precision** is of the rows the scorer marked with that category, how many were truly that
  category. It moves when a false positive arrives from *another* category's text, which is how
  cross-category confusion shows up.
- **recall** is of that category's rows, how many the scorer caught.
- **flagged (any category)** is the number a parent would feel: of 455 harmful rows per language, how
  many raised any flag at all. Its companion is the false-positive rate on the safe rows — 133 in
  English and 136 in Arabic, of which the **hard negatives** (benign text that reuses the category's
  vocabulary: "the wifi is pathetic today", "my knife skills in cooking class") are the ones that
  punish a scorer keying on single words. Text is unique within a language, so the safe rate is not
  diluted by copies of the same sentence.
- The **0.50 threshold** is arbitrary but fixed: the diagnostic endpoint flags at 0.60 and 0.85
  (`_severity` in `model.py`), and a category needs to be well clear of the threshold to count.

## What the set is, and is not

The dataset is 1,179 rows (588 EN / 591 AR) generated deterministically from seven template banks —
377 positive templates, 176 hard negatives and 106 generic safe messages across the two languages,
from which the generator draws 455 positive rows, 84 hard negatives and 49/52 safe rows per language. The
template count is the number that matters for the gate's interval, and it is what the second author pass
on `self_harm` (21/26 -> 41/46) and `grooming` (20/23 -> 40/43) moved: at a fixed 65 rows per category the
sample now draws from nearly twice as many independent patterns.
It
contains the *social pattern* — secrecy, coercion, isolation, threat, group targeting, pressure — in
teen register, and **names the thing** the message is about. A positive that names nothing is not a
positive: "delete this chat before your mum sees it" was labelled `substance_use` in the first draft
and could not be told from grooming, so it was rewritten to name the vape (#262 review).

The content boundary is deliberate and is written at the top of `eval/banks/__init__.py`: no method,
dosage, price, sourcing route, weapon construction, injury detail or graphic description, in either
language. **Name the thing, never the method.** A detector that only fires on method text is a
detector that misses grooming, and a repository that carries method text teaches it.

Consequence for reading the numbers: a metric computed from this set measures **paraphrase and
register**, not the easy lexical cases. The rules layer does catch its own vocabulary — that floor is
pinned by `tests/test_eval_harness.py::test_regex_floor_catches_its_own_vocabulary` — so a low recall
here means the scorer missed real messages, not that the scorer is broken.

**Size, and the decision behind it.** Plan 4.2 asks for 2,000 + 2,000 snippets. This set is ~590 per
language, and it grows **through templates or new sources, never through more slot fills of the same
template**: the generator caps each template at 5 rows, and `--per-category` above
`templates × 5` raises rather than filling. Claude's ruling on #262: the floor stays as written, and
the count grows through author passes (self_harm and grooming first, because they carry the Phase 4
gate). One template filled 65 times is one item, not 65 — the recall interval it produces is a
fiction.

Known limits, stated rather than discovered later:

- **Synthetic only.** Every row comes from a template bank, so vocabulary is as broad as the bank
  author imagined. Public corpora and, eventually, parent-reported false negatives (with consent and
  no child identifying data) are the next source; `eval/schema.md` fixes the provenance field so they
  can be added without renumbering.
- **Multi-label only where the overlap is real.** Each row carries its bank's category plus declared
  extras (`ALSO_LABELS_EN` / `ALSO_LABELS_AR`); combinations no bank declares are not represented.
- **Register has one author per bank.** No second reader has checked that the Arabic sounds like a
  teenager rather than a translation — the same gap TR-54 names for the app's Arabic.
- **No age-conditioned scoring.** `AGE_RANGE` is recorded per bank but `analyze_text` accepts
  `child_age` without using it, so the set cannot yet show an age-dependent miss.
- **The set is 74 % harmful while real messages are mostly safe**, so a precision number measured
  here will look better than what a parent sees. The safe side must grow with the positives.
- **No dev/test split yet.** Before 4.1 tunes a prompt, a `split: dev|test` field per template is
  needed, or the published set becomes the tuning set.

## The hosted scorer (plan 4.1)

The table above measures the **rules layer**, which is the floor. The scorer that is supposed to beat it
is a hosted multilingual model, and it is wired as an evaluation scorer only — `eval/deepseek_scorer.py`,
never imported by `model.py` or by the API.

**Why eval-only.** An evaluation sends synthetic messages, written by us, about imaginary children. A
production scorer would send a real child's message to a third party. Those are different decisions, and
keeping the module inside `eval/` makes the second one a deliberate change rather than a flag somebody
flips. Moving it out is the conversation `docs/ROADMAP.md` 4.1 and 4.4 exist to have.

```bash
cd services/ai-engine
export DEEPSEEK_API_KEY=...          # or the repository secret, in CI
python -m eval.run_eval --scorer deepseek --json deepseek-result.json
python -m eval.run_eval --scorer deepseek --limit-per-category 5   # a cheap smoke run first
```

Cost is per row and cached by `(model, text)` in `eval/.deepseek-cache.json` (gitignored), so re-running
an unchanged set is free. The manual workflow `.github/workflows/ai-eval-deepseek.yml` does the same on
CI; it is `workflow_dispatch` rather than push-triggered because every run bills the dataset and the
answer only changes when the banks, the prompt or the model do. **GitHub will not dispatch a workflow
that is not on the default branch**, so the first run happens after this lands.

**Measured 2026-10-21.** The first billed run — `ai-eval-deepseek` workflow `39628473359` on `main` —
scored all 1,179 rows with `deepseek-chat` and no prompt tuning. The prompt was not tuned against any
run's results and quotes no rows, but it is **not held out**: the same author wrote the prompt and the
templates, and the prompt's category descriptions follow the templates' themes — its `self_harm` line,
"hopelessness, goodbye messages, concealing injury, being a burden", is close to the design note at the
top of `eval/banks/self_harm.py`. The `dev`/`test` split below is what would make this a held-out
estimate:

|---|---|---|

**The Phase 4 gate is met on this set.** Recall ≥ 0.85 on `self_harm` and `grooming` at precision ≥ 0.6,
in both languages: EN `self_harm` 1.00/1.00 and `grooming` 0.99/0.80; AR `self_harm` 0.97/0.98 and
`grooming` 1.00/0.69. On the same rows the rules layer scores **0.00 recall in all seven Arabic
categories**.

**What this does not say.** Four limits, in order of how much they could move the number:

- **The rows come from template families.** Five rows share a template's wording, so a model that
  recognises one may recognise its siblings. The `dev`/`test` split noted below is what would turn this
  into a population estimate rather than a measure of this corpus.
- **`cyberbullying` precision is poor (0.36 / 0.38)** because its rows are also flagged with the category
  they overlap. The recall of 1.00 is real; the precision is the cost of a coarse taxonomy.
- **One model, one run, one threshold.** No variance estimate. A second model and a repeated run would
  say how much of the gap between categories is signal.
- **Every false positive in both languages is a hard negative** — a message that sounds harmful and is not.
  That is the shape a parent experiences as a false alarm, and it is 1 of 84 English rows and 4 of 84 Arabic.
- **Not in production, deliberately.** These are evaluations on synthetic messages. A production scorer
  sends a real child's message to a third party — the 4.1-versus-4.4 decision, which this number does
  not make.

## Reproducing a row

Each row carries `provenance = {kind, bank, template_index, seed}`, so a surprising item can be
traced to the exact template and the seed that filled its slots:

```bash
cd services/ai-engine
python -c "import json;[print(r['text']) for r in map(json.loads, open('eval/dataset.jsonl',encoding='utf-8')) if r['provenance']['bank']=='self_harm' and r['provenance']['template_index']==3][:5]"
```

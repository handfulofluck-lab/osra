### OSRA Kids iPhone: parent ring command (#750)

- Add the parent `ring` and `stop_ring` commands with a five-minute cap, an AlarmKit backend on iOS 26+, persistent ring state, and parent-PIN access.
- Report child dismissals, PIN stops, parent stops and timeout through server-owned alert body keys; coalesce dismissal pushes for 60 seconds with atomic, expiring Redis reservations while keeping every event.
- Check restart timeouts against the original command's server timestamp. Online early timeouts resume with the remaining seconds; offline restart expiry stays pending with a fresh monotonic timeout until a positive answer reports `afterRestart`, with its own localized parent line.
- Add localized parent rendering and an update-required reason for older iOS versions. Bureau-approved English and Arabic are included; final-head screenshot review, full CI, independent verification, and the Mac test-bed KR01 and escape rows remain required before merge. No physical-device evidence or Critical Alerts entitlement request is claimed here.
- Wake a locked or suspended iPhone ring with a child-topic APNs alert: priority 10, time-sensitive, mutable content, the bundled `ring_notification_*` loc-keys and the constant `osra-ring` collapse key, with no command id, child data, wake marker or OSRA text. A new notification service extension polls only the `ring` command and best-effort schedules the existing AlarmKit ring; a started ring uses the system ringtone, while the approved fallback for a failed or empty fetch keeps the default sound for up to 30 seconds, and opening starts the full five-minute ring. The extension never marks the ring command as `failed`; a failed AlarmKit schedule leaves the command for the app's full drain.
- Request notification authorization at pairing so the first background ring push is not silently dropped before the child has seen a ring screen.
- Count a dismissal only when the active main alarm leaves the live scheduled set, discard stale schedule-cancel snapshots, accept at most one dismissal report per six-second chain interval, keep audio start idempotent while the ring is active, and cap server-side dismissal rows at ten per ring so a feedback loop cannot flood the parent.

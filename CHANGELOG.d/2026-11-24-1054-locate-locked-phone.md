### Child agent (Android) — reliable `locate_now` on locked/dozing phones (#1054)
- Acquire a bounded `PowerManager.PARTIAL_WAKE_LOCK` (`LocatePolicy.WAKE_LOCK_TIMEOUT_MS = 45_000L`, reference-counted via `LocateWakeLock`) in `CommandDispatcher.locateNow` before starting `LocationService`, always releasing it in `finally` when `LocationService.locateNowOnce` completes (or if FGS start fails).
- Extract shared one-shot location acquisition into `LocationFixFetcher` with a two-stage fresh-fix fallback (`PRIORITY_HIGH_ACCURACY` for 15 s, then `PRIORITY_BALANCED_POWER_ACCURACY` for 10 s, then `lastLocation` if `<= 5 min` old) and direct background fallback on `CommandDispatcher`'s scope if `startForegroundService(LocationService)` throws on API 31+ (still gated by `LocationStartPolicy` and consent pause).
- Guard `LocationService.onStartCommand`'s `startUpdates(STATIONARY_INTERVAL_MS)` with `updatesStarted` (reset in `onDestroy`) so `ACTION_PING_NOW` does not tear down active fused location callbacks.
- Persist FCM registration tokens synchronously with `runBlocking` in `FirebaseMessagingSvc.onNewToken` before async upload, and proactively hydrate missing push tokens via `PushTokenHydrator` (`runCatching { FirebaseMessaging.getInstance().token }`, safe in FCM-free builds) in `CommandPoller.syncPushToken`, `PairingActivity.startAgent`, and `FamilyShieldApp.onCreate`.
- Verification scope: verified by Android JVM unit suites (`testFullDebugUnitTest` and `testPlayDebugUnitTest`) plus two planted-mutant checks; hardware verification on a locked handset remains pending on a physical device.

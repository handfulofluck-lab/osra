### iOS child agent — push token, command queue and a working device wake (5.5 PR D, #372)
- The app registers for remote notifications. `PushTokenRegistrar` uploads the APNs token
  (`POST /v1/devices/:id/push-token`, device token) once per token and paired device, retries a failed upload,
  and forgets it on unpairing.
- A wake push (`{"w":"1"}`), or opening the app, runs `CommandDrainer`:
  - it polls `GET /v1/devices/:id/commands?ack=1` and acks every command;
  - `rules_updated` and the consent commands re-sync the rules, once per drain;
  - any command the iPhone can't carry out (lock, ring, …) is acked `failed` with `unsupported_on_ios`, so the
    parent sees why instead of a silent "delivered";
  - a 428 on the poll syncs, which clears the rules.
- `Info.plist` gains `UIBackgroundModes: remote-notification`, and the app's entitlements gain `aps-environment`.
- **Server fix (`services/api/src/lib/push/apns.ts`):**
  - The child-device wake now goes to Apple as `apns-push-type: background` at priority 5, as Apple requires for
    a `content-available` push. Before, it was `alert` at priority 10, with nothing to show.
  - It goes to the child agent's topic, `APNS_DEVICE_BUNDLE_ID`. Under the parent app's topic, Apple refuses it
    with `DeviceTokenNotForTopic`, and the server then cleared the child's token as dead.
  - Without `APNS_DEVICE_BUNDLE_ID`, no wake is sent and the token is kept.
  - `test/push.test.ts` pins this.
- If iOS refuses a new bedtime window, the old bedtime activity is stopped and its shield cleared. Claude raised
  this on #380.
- Tests: `DeviceCommandsTests` (command table, drain and acks, 428, token upload policy), two server tests, and
  live cases 7 and 8. The job now requires 8 passed and 0 skipped.
- Not yet: a real APNs token, a real wake, and shields updating on a locked device. Those need the signed build
  (5.1).

- API (osra-security#82, follow-up to #1230): on a completed pairing whose stored grants are all ready, the phone's #1208 setup notice is answered `409 {retry:"awaiting_report"}` (Retry-After 30) until a capabilities report arrives after the notice was first seen, instead of a terminal 200 drop. This lets a notice that is ahead of its telemetry become the upgrade notice. A report after it that shows every grant, or no report within 10 minutes, still drops it as a stale first-setup retry. The upgrade notice (new or re-raised row) now carries its own `pushDeliveryId`/`pushDeliverySeq`, so a parent phone that already showed the first-setup notice shows the upgrade once, and a duplicate wake stays quiet.
- A pairing whose first notice was stored under the pre-#1208 key keeps that one row on an upgrade notice: it is raised again in place instead of a second row being added.

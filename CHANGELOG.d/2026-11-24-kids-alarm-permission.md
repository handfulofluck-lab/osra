- OSRA Kids now asks for the **Alarms** permission where the child can see why — next to Screen Time on the status screen, before any ring — instead of the system prompt arriving cold the first time a parent rings the phone. If the child closes it, the request is refused and nothing sounds while the parent believes the phone is ringing; the row then says **"Ringing is off on this iPhone"** and its one button opens Settings, which is the only place iOS lets the permission be turned back on. An approved phone, or one whose build cannot ring at all, shows no row: a green "ringing is on" line is noise, and blaming a child for a build fact is wrong. The status is re-read whenever the app comes back to the foreground, so changing it in Settings is reflected without a relaunch. Wording is the Arabic Language Bureau's `604` `7122208660` — including `alarm_setup_button`, which the UI/UX spec left open — copied verbatim into both `.strings` tables, with `المنبّهات` quoting Apple's own Settings label. `AlarmRingingRowTests` pins the three states and both tables; the mutant that fails it is a refused phone offering the ask again, which iOS will never show. Not in this change: the parent-app line (`alarm_parent_line`) is K31's screen and its schema work, and the Bureau's AR frames at 320 pt / 200 % still need the device row (#880).

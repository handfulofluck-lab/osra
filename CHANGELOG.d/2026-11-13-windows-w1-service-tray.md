### Windows — the W1 service and tray foundation (#623, PR #754)
- Split the desktop agent into a shared library, a LocalSystem service and a per-user tray. The service owns network/rule state, enforcement and telemetry; pairing and interactive actions stay in the user's session.
- Added a per-session typed named pipe with SYSTEM/session-user access control and OS-derived client identity checks. Commands and capability reports contain no parent PIN or device credentials.
- Release builds ignore environment identity, endpoint, secret and PIN overrides; they use `https://api.osratech.com`. Pairing has no server field and reports the interactive user's administrator capability.
- Bound the service to the launched tray PID and co-located image, required a session-0 pipe server before `hello` without opening a SYSTEM process/token, denied NETWORK on the pipe, and derived session SIDs from the session token. Restriction state is replayed on reconnect, with a 20-second WTS offline fallback and tamper reporting. SOS is limited to one POST per device per 60 seconds and desktop capabilities carry `source: tray`; foreground usage remains self-reported until W2.
- Added a device-level JSON restriction store in a protected SYSTEM/admin-only directory so future sessions inherit restrictions and offline fallback re-arms every 20 seconds. Missing state starts empty; corrupt or insecure state fails closed immediately; protected temporary files use `FileMode.CreateNew`, with stale files replaced only after the directory trust check. Save failures retain in-memory enforcement and log/raise one tamper alert per failure episode; unlock/resume clears disconnected sessions too. A CI-only SYSTEM service probe verifies the real pipe, ACLs, store recovery and persisted unlock without touching the development PC.
- Composed-host review repairs singleton worker/coordinator resolution, pairing startup and full-duplex pipe lifetime. The real client owns one `hello` per connection; rejected clients are disconnected before a genuine retry, and first-instance pipe creation, session discovery and per-session failure backoff protect restart behavior. Device restrictions merge over stale session records and restored sessions start a fresh offline grace period.
- SOS uses an acknowledged `sos_result`: failed posts do not consume the throttle window and are retried ahead of bounded ordinary traffic; success text appears only after service acknowledgement. Save failures are high unless unreadable state survived restart, and use a separate parent-facing title. Desktop-only capability fields are rejected for phone clients, Standard accounts are not missing permissions, and pre-connection interactive features report `degraded`.
- CI tests Debug and Release and publishes both hosts and their dependencies together as the unsigned win-x64 artifact `OSRA.Windows-W1-unsigned`. CI: 354/354 desktop tests in both configurations, including real pipe acceptance/ACLs, a two-worker quiet-connection loopback, restart recovery, SOS acknowledgement/retry and production composition; no clean Windows-machine verification has happened yet.
- This is not an external-tester release: W1b PIN hashing and W3 installed-directory ACLs, MSI/service recovery and signing are still required. W2 DNS/firewall/browser-policy work and the W4 updater are not included.

### Parent app — every app choice is a picker with real names and icons (#868, U33)
- One full-screen multi-select picker (`lib/features/rules/app_picker.dart`) replaces both package-id
  dialogs: the always-allowed "Add app" list, the payment-app shortcut and the app-rule button all open
  it. Rows show the app's icon (a letter avatar in the brand tint until the server has one), its name and
  a checkbox; no package id is displayed anywhere, and search matches the app name only.
- Routines ask for apps the same way: the two comma-separated fields are gone, replaced by icon chips
  and a "Choose from child's apps" button per list.
- The app-rule row shows icon + name (the package id line is removed), and an app that already has a
  rule is greyed in the picker with that rule as its subtitle.
- New: `InstalledApp.iconUrl` (nullable; an empty string is treated as "no icon yet") and
  `installedAppsByDeviceProvider`, which keeps each device's inventory apart so a child with two phones
  gets rows grouped under each device. With one device there are no group headers; the same app ticked
  in one group is ticked in the other.
- Not in this PR: the "also block its website" offer (U33 B) and the web-filter cards (U33 C). The exact
  new strings U33 asks for ("Choose apps", "Add {n} apps", the child-name empty state) are with the
  Arabic Language Bureau; this PR reuses the existing strings, so no Arabic text changed.
- Verification: no Flutter SDK on the authoring host, so `flutter test` and `flutter analyze` are CI
  evidence on the PR, not a local run. The Android-side icon upload (`kimi/u33-app-icons`) is Kimi's
  half; until it lands every row draws its letter avatar.

### API — email can go out through AWS SES, with no key in the environment (Play decision 11 A)
- **What a parent will see:** nothing changes about the emails themselves — the same reset, invite and digest
  templates — but once `EMAIL_PROVIDER=ses`, they are sent by SES from `no-reply@osratech.com` rather than by a
  third-party API, which is what the privacy policy and the data-safety answer describe.
- **No credential in the environment or the repository.** On Fargate the SES client takes the task role from the
  default provider chain; only `EMAIL_FROM` is needed. `SESv2Client` is constructed lazily, so importing the
  email module never requires AWS to be configured.
- **The Resend sender stays until Karim's SES identity and sandbox exit are live**, and the unconfigured
  fallback is unchanged: with neither provider set, the sender logs the envelope instead of sending. Removing
  Resend is a one-line follow-up once SES is the default in staging.
- **Error classification matches the existing sender**, because callers branch on it: throttling, 408, 429, 5xx
  and a network failure are retryable; any other 4xx (`MessageRejected`, an unverified address) is not.
- Rows: `email.test.ts` gains three — the exact `FromEmailAddress`/destination/body SES receives, a single
  recipient still sent as a list, and the four error classes. API suite **810/810**.

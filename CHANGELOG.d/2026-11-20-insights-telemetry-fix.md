### Child agent & API — restore social alerts, incognito/DoH filtering, opt-in search safety reporting, and foreground usage attribution (#830, #863, #938, #939, #941)
- **Window-verified social capture (`osra-security#44`):** `SocialCapture` verifies window ownership across `activeRoot`, `event.packageName`, and `event.source` via `WindowOwnershipPolicy` before reading any accessibility text or child nodes, and `SocialHeuristics.extractCandidates` collects recent non-empty messages so older text cannot shadow short harmful replies.
- **Opt-in search reporting, durable queue & local fallback union (#939, `osra-security#45`):** `RuleRepository.searchMonitoringEnabled()` defaults to `false` until `RuleSet.searchMonitoring == true` is explicitly granted (`services/api` schema/routes enforce it server-side and drop unneeded URL data); Full-flavor `AccessibilitySearchCapture` (Play remains `NoopSearchCapture` per ADR-0039) verifies window ownership before inspecting nodes and enqueues only confirmed submitted queries through durable `pending_scans` (`SocialScanQueue`); `POST /v1/content/search-event` unions AI and expanded EN/AR `SEARCH_LOCAL_PATTERNS`.
- **Browser DoH canary/bootstrap sink (#941):** `DnsFilterPolicy` sinks known DNS-over-HTTPS bootstrap/canary hosts (`REASON_DOH_BYPASS`) while web filtering is active so browsers fall back to the local VPN DNS filter even in incognito mode, without inflating parent block-attempt alerts.
- **Foreground usage attribution (#830):** `UsageReporter` delegates transition state to `ForegroundSessionTracker`, clearing `activeForegroundPkg` on `com.android.systemui`, own overlay windows, and screen-off events so system UI never retains foreground usage attribution.

### Child agent, parent app & API — restore social alerts, incognito/DoH filtering, opt-in search safety reporting, and foreground usage attribution (#830, #863, #938, #939, #941)
- **Window-verified social & search capture (`osra-security#44`, `#58`):** `SocialCapture` and Full-flavor `AccessibilitySearchCapture` verify window ownership across `activeRoot`, `event.packageName`, `event.source` (acquired lazily inside `try/finally` after fast gates), and descendant `node.packageName == expectedPackage` via `WindowOwnershipPolicy` before reading any accessibility text, flags, or children; `AccessibilitySearchCapture` and `SearchQueryParser` further restrict search extraction strictly to unfocused provenance-verified native browser address controls (`BROWSER_ADDRESS_BAR_IDS` owned by `BROWSER_PACKAGES`) carrying an explicit search-results URL (`parseSearchUrl`), leaving `WebView` titles, ordinary browser content, and dedicated search apps off; and `SocialHeuristics.extractCandidates` collects recent non-empty messages so older text cannot shadow short harmful replies.
- **Opt-in search reporting, durable queue & server-verified grant revision (#939, `osra-security#45`, `#53`-`#57`, `#59`):** `RuleRepository.searchMonitoringEnabled()` defaults to `false` until a fresh rules sync confirms `RuleSet.searchMonitoring == true` with committed `SearchOptInCoordinator` state and a valid server-issued `searchMonitoringRevision` (`parent-app` exposes an explicit `Search safety` opt-in toggle via dirty-tracked narrow `PATCH` writes in `SocialScreen` and disables/revision-guards in-flight save mutations so unrelated or delayed saves cannot overwrite or drop choices; `services/api` omits absent `searchMonitoring` on `PATCH` updates, bumps `searchMonitoringRevision` when `searchMonitoring` changes, and verifies matching active `searchMonitoringRevision` in `POST /v1/content/search-event` returning `409 stale_search_grant` on mismatch); Full-flavor `AccessibilitySearchCapture` (Play remains `NoopSearchCapture` per ADR-0039) enqueues only confirmed submitted queries through durable `pending_scans` (`SocialScanQueue`) bound to `searchMonitoringRevision`, holds queued search rows until fresh server sync is confirmed after startup (`RuleRepository.kt:97`), honors `ConsentState` pause and requires verified pre-grant backlog/opt-out cleanup before uploading, purges refused `403`/`409` search uploads without retry, and derives critical alert categories from the full AI/local union while prioritizing critical categories under concern bounds.
- **Browser DoH canary/bootstrap sink (#941):** `DnsFilterPolicy` sinks known DNS-over-HTTPS bootstrap/canary hosts (`REASON_DOH_BYPASS`) while web filtering is active so browsers fall back to the local VPN DNS filter even in incognito mode, without inflating parent block-attempt alerts.
- **Foreground usage attribution (#830):** `UsageReporter` delegates transition state to `ForegroundSessionTracker`, clearing `activeForegroundPkg` on `com.android.systemui`, own overlay windows, and screen-off events so system UI never retains foreground usage attribution.

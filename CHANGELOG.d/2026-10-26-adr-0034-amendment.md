### ADR-0034 amended — the server decides `not_supported`, and the update gate never blocks a data right (roadmap 5.8)
- This is a design change only; ADR-0034 PR 1 builds against it. It comes from Ahmed's security review on
  #371, and Claude accepted all of it.
- `not_supported` comes from a server table of build facts, keyed by app and flavour. A device that claims it
  for a feature outside its row is shown `unavailable`, which counts as a fault. Commands the table rules out
  fail at once, without waking the phone.
- `capabilities` gets a strict schema with a 4 KB cap. `X-OSRA-Client` is a hint, never a security control:
  it has a 64-character cap and a strict pattern, and only device requests write a device's build. The
  server's receipt time is the only freshness clock.
- The 426 gate exempts logout, logout-all, consent withdrawal and child deletion, so an old app can always
  withdraw consent.
- iOS: one refusal reason, `not_supported` (renamed from `unsupported_on_ios` in the iOS PR next to this
  one), the iOS grant keys and features table, and, later, the APNs host chosen per device from the build
  flavour.

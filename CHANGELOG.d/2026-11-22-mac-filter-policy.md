### Mac step (iii): the content filter's decision table, the daemon→extension snapshot and an honest capability report (#988)
- `apps/child-ios/MacAgent` gains `OSRAMacAgentFilter`: a Foundation-only target holding `FilterPolicy` (the ADR-0015 decision table — pause > explicit allow > explicit block > blocked category > SafeSearch > allow, with DNS-label suffix matching), `PolicySnapshot`/`PolicySnapshotStore` (one JSON file the root daemon writes atomically at `0600`, refuses to replace when the file is not its own, and refuses to roll `version` backwards) and `FilterStatus`.
- SafeSearch on macOS is a **redirect** that sets the engine's own safety parameter, not the DNS sinkhole's resolver rewrite; a content filter has no CNAME to rewrite. A blocked or paused host still outranks the redirect, as on Android.
- `MacCapabilityReport` stops declaring `web_filter` a constant: it reports `ready` only for a running provider with a policy it could read, `degraded` for a running provider without one, and `unavailable` otherwise. `pause_internet` stays `unavailable` until its own path exists.
- Tests: the decision table (matching, precedence, SafeSearch, enforcement hosts, normalising decode), the snapshot store's three properties (crash-safe read, mode/owner refusal, monotonic version) and the capability mapping. Each names the mutant it kills.
- Not in this change: the `NEFilterDataProvider` subclass and its signed `.systemextension` bundle, `WebVisit` reporting (its own issue behind the consent gate), the menu-bar app, the Safeguard card and the installer. Signed activation and the Safari/Chrome block stay a device acceptance row on #628.

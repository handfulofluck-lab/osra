### Child Android — fresh installs fetch and retry rules without a parent save (#1130)
- Every scheduler start now enqueues the existing immediate rules worker instead of relying on its six-hour periodic job or a parent-triggered `rules_updated` push. Pairing uses that same single startup request rather than enqueueing a duplicate. A genuine package replacement and every foreground-service restart share one coalesced startup worker (`REPLACE`), covering in-place updates and process death; push-driven refreshes keep their separate `APPEND_OR_REPLACE` behavior.
- A paired device whose rules cache is still empty returns WorkManager `retry`, so backoff continues until rules arrive. The applied-rules version remains null until a fetched rule set is persisted, and the existing empty-cache fail-closed enforcement is unchanged. A failed rules save returns the previous durable cache (or null), never the unpersisted fetch, so a later retry can succeed honestly.
- JVM tests cover immediate startup, coalesced enqueue policy, the worker's paired-empty outcome, package replacement, service restart and a real failed-save-then-successful-retry path. Fresh-install Pause behavior still requires independent hardware verification.

### Android + API + Parent — first phone setup no longer pages generic tamper noise (#1127)
- New pairings use a server-owned 30-minute setup window. Only tamper events tied to a grant currently reported missing are held for security audit; they do not push, publish, appear in alerts or exports, or get acknowledged. Held retries use a separate `held|` key namespace so the same tamper after setup creates a new visible, pushed alert. SOS and unrelated tamper events remain visible.
- Authenticated all-required telemetry emits one deduped protected alert. If both its first write and rollback fail, a later all-ready report retries the alert instead of leaving completion without it. A shared poll/scheduler evaluator emits one missing-steps alert at 30 minutes, or generic incomplete copy when no reliable step count exists. Existing paired devices are backfilled without an alert burst, and the approved data-cleared path keeps one named reinstall alert.
- Parent Phone setup shows localized steps left only for Android responses carrying the completion field, preserving repair copy for iOS and legacy responses. Completion, timeout and data-clear alerts have validated English/Arabic titles and bodies, localized grant labels and generic lock-screen bodies; unrelated Arabic alerts keep their stored bodies.
- ADR-0047 and migration 0046 document the server state and paired-device backfill. Focused suites include fail-first held-event, completion, failed-rollback recovery, poll/scheduler, EN/AR, legacy-platform and malformed-parameter coverage. Independent R3/security and Bureau review plus full live verification are recorded on the PR when complete; no handset claim is made here.
